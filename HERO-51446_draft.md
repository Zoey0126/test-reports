# HERO-51446 Test Report

The backend validation for Member Number Configuration → Auto Generating Rule → Prefix in System Configuration : Member Module was insufficient and allowed a JavaScript attack using Burp Suite's intercept feature. A malicious payload could be injected into the Prefix request parameter, saved through the Member Module save request, and executed in the browser. The fix is delivered in backend version 1.2.117.0, where the data is saved but secured from executing the code.

## Functional Testing

### 1. Prefix Payload Injection via Intercepted Save Request

#### 1.1. Saving the Malicious Prefix Payload Does Not Execute Script

**Prerequisite(s):**
1. Burp Suite or similar intercepting proxy software is available.
2. The tester is logged in to the admin portal with access to System Configuration > Member Module.
3. Backend version 1.2.117.0 is deployed.

**Step(s):**
1. Open Burp Suite, go to the Proxy tab and open its built-in browser.
2. Set the intercept mode to "Off".
3. Visit System Configuration > Member Module and input dummy values for Member Number Configuration without clicking Save.
4. Set the intercept mode to "On" in Burp Suite, then click "Save" in the admin portal.
5. Modify the request parameter "Prefix" to the JavaScript payload recorded in the JIRA ticket.
6. Click "Forward" until the request is completed.
7. Observe the page displayed after the new configuration is saved.

**Reproduction Result(s):**
1. Before the fix, the backend validation for the Prefix parameter was insufficient and the malicious payload was accepted.
2. After the new configuration was saved, the page redirected to the listing page and alert boxes were prompted, which proved that the malicious code was executed.

**Fix Result(s):**
1. The configuration data is saved but secured from executing the code.
2. The page redirects to the listing page without any alert box or script execution.
3. No malicious code from the Prefix payload is executed in the browser.

#### 1.2. Stored Prefix Value Is Rendered Without Script Execution

**Prerequisite(s):**
1. A member number configuration has been saved with the malicious payload in the Prefix parameter through an intercepted save request.
2. The tester is logged in to the admin portal with access to System Configuration > Member Module.

**Step(s):**
1. Open System Configuration > Member Module.
2. Check the member number configuration listing page.
3. Refresh the listing page.
4. Reopen the saved member number configuration.
5. Observe the browser for any script execution.

**Reproduction Result(s):**
1. Before the fix, alert boxes were prompted when the page containing the saved configuration was loaded, which proved that the stored payload was executed.
2. The malicious code stored in the Prefix field was executed in the browser every time the page was opened.

**Fix Result(s):**
1. The stored prefix value is displayed without executing any script.
2. No alert box appears on the listing page, after refreshing the page, or when the configuration is reopened.
3. The configuration data remains saved.

### 2. Member Number Configuration with Valid Prefix

#### 2.1. Valid Prefix Is Saved Successfully in the Auto Generating Rule

**Prerequisite(s):**
1. The tester is logged in to the admin portal with access to System Configuration > Member Module.
2. A valid prefix value for Member Number Configuration → Auto Generating Rule is prepared.
3. Backend version 1.2.117.0 is deployed.

**Step(s):**
1. Visit System Configuration > Member Module.
2. Input the valid prefix and the other member number configuration values.
3. Click "Save".
4. Reopen the member number configuration.

**Reproduction Result(s):**
1. Before the fix, the reported defect was limited to the malicious payload used for the script injection.
2. A valid prefix was accepted by the save request, so this flow was not affected by the vulnerability.

**Fix Result(s):**
1. The member number configuration with the valid prefix is saved successfully.
2. The saved prefix is displayed correctly when the configuration is reopened.
3. No validation error is displayed for the valid prefix.

#### 2.2. Saved Prefix Is Applied to the Auto-Generated Member Number

**Prerequisite(s):**
1. The member number configuration is saved with a valid prefix in Auto Generating Rule.
2. The member module is available for creating a new member.

**Step(s):**
1. Open the member module and create a new member.
2. Check the member number generated by the auto generating rule.

**Reproduction Result(s):**
1. Before the fix, the reported defect was limited to the Prefix validation for malicious input.
2. The auto generating rule flow is included as a regression check of the Prefix configuration.

**Fix Result(s):**
1. The member number is generated successfully for the new member.
2. The generated member number follows the saved prefix configured in the auto generating rule.

### 3. Regression on Member Module Configuration

#### 3.1. Member Number Configuration Can Be Edited and Saved After the Fix

**Prerequisite(s):**
1. A member number configuration with a valid prefix already exists.
2. The tester is logged in to the admin portal with access to System Configuration > Member Module.

**Step(s):**
1. Open System Configuration > Member Module.
2. Open the existing member number configuration.
3. Change the prefix to another valid value.
4. Click "Save" and reopen the configuration.

**Reproduction Result(s):**
1. Before the fix, the reported defect was limited to the Prefix parameter used for the script injection.
2. The normal edit and save flow of the member number configuration was not affected and is included as a regression check.

**Fix Result(s):**
1. The updated prefix is saved successfully.
2. The updated value is displayed correctly when the configuration is reopened.
3. No script execution or alert box is observed during the edit and save flow.

#### 3.2. Other Member Number Configuration Fields Are Saved Correctly

**Prerequisite(s):**
1. The tester is logged in to the admin portal with access to System Configuration > Member Module.
2. Valid values are prepared for the member number configuration fields other than the prefix.

**Step(s):**
1. Visit System Configuration > Member Module.
2. Input valid values for the other member number configuration fields.
3. Click "Save".
4. Reopen the configuration and compare the displayed values with the input values.

**Reproduction Result(s):**
1. Before the fix, the reported defect was limited to the backend validation of the Prefix parameter.
2. The other member number configuration fields saved correctly before the fix, so they are included as a regression check.

**Fix Result(s):**
1. The other member number configuration fields are saved successfully.
2. The saved values match the input values when the configuration is reopened.
